## Highlights

- **Set up Kanata from the app:** while `kanata.service` is missing, the main view shows a hint and the first-start screen a button that open **Set up Kanata**. The dialog:
  - creates and enables the user unit `~/.config/systemd/user/kanata.service` for the open configuration (no root needed). It never replaces an existing unit and starts the service only when Kanata already has device access; otherwise it starts at the next login.
  - checks whether Kanata can read `/dev/input` and write `/dev/uinput`. For anything missing it lists the root commands from the Kanata setup guide (`uinput` group, group membership, `uinput` module, udev rule) to copy. **Kanata Studio never runs these commands itself.** Log out and back in afterwards so new groups apply.

## Fixes

- **Saving and testing now restart Kanata instead of reloading it.** Kanata exits on `SIGUSR1`, so a service with `ExecReload=kill -USR1` only came back through `Restart=` after `RestartSec` (several seconds without your mapping), and a service without `ExecReload` could not be reloaded at all. The app now uses `systemctl --user restart kanata.service`.

## Install

Download `install.py` from the assets below and run `python3 install.py`. It downloads this release, verifies the checksums, and installs the app (plus the plugin on Omarchy). Run it again to update an existing installation. Use `--app-only` to skip the plugin and `--check-only` to only verify the downloads.

Requirements: x86_64 Linux with glibc 2.36+, Python 3.10+, and a desktop graphics stack (Mesa or another GLVND driver). Built on Debian 12; smoke-tested on Debian 12, Ubuntu 24.04, and Fedora 44. Kanata itself must be installed separately. See the README.
